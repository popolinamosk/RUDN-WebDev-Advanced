## Purpose
Описывает поведение системы при отметке карточки как выполненной (isDone).

## ADDED Requirements

### Requirement: Элемент управления на карточке
Каждая карточка на доске SHALL содержать видимый элемент управления (чекбокс), которым пользователь может поставить или снять отметку `isDone`.

#### Scenario: Отметка карточки как выполненной
- **WHEN** пользователь устанавливает чекбокс на карточке
- **THEN** отправляется `PATCH /cards/:id` с телом `{ isDone: true }`

#### Scenario: Снятие отметки выполнения
- **WHEN** пользователь снимает чекбокс на карточке
- **THEN** отправляется `PATCH /cards/:id` с телом `{ isDone: false }`

### Requirement: Сохранение на сервере
Система SHALL сохранять отметку `isDone` на сервере при изменении через `PATCH /cards/:id` с телом `{ isDone: boolean }`.

### Requirement: Переживание обновления страницы
Значение `isDone` SHALL загружаться с сервера и отображаться корректно после обновления страницы.

### Requirement: PATCH эндпоинт для отметки выполнения
- **Метод:** `PATCH`
- **Адрес:** `/cards/:id`
- **Тело запроса:** `{ isDone: true }` или `{ isDone: false }`

### Requirement: Валидация isDone (middleware)
Значение `isDone` SHALL быть `boolean`. Негодное значение SHALL отклоняться кодом 400. Проверка SHALL реализована в middleware, а не в контроллере.

#### Scenario: Допустимое значение isDone
- **WHEN** запрос содержит `{ isDone: true }` или `{ isDone: false }`
- **THEN** запрос проходит валидацию

#### Scenario: Недопустимое значение isDone
- **WHEN** запрос содержит `{ isDone: "true" }`, `{ isDone: undefined }`, `{ isDone: 0 }` или `{ isDone: 1 }`
- **THEN** сервер отвечает 400 с JSON `{ "error": "..." }`

### Requirement: Карточка не найдена (контроллер)
При изменении несуществующей карточки сервер SHALL возвращать 404. Решение принимает контроллер; сервис лишь сообщает, что карточки нет.

#### Scenario: Обновление несуществующей карточки
- **WHEN** отправлен `PATCH /cards/:id` с несуществующим ID
- **THEN** сервер отвечает 404

### Requirement: Сервис без HTTP-зависимостей
В сервисе НЕ должно быть `req`, `res` и статус-кодов. Только бизнес-логика.

### Requirement: Разделение слоёв
- Роутер: одна строка — привязка `PATCH /cards/:id` к контроллеру.
- Контроллер: функция `patchCardDone`.
- Сервис: функция `updateCardDone(cardId, isDone)`.
