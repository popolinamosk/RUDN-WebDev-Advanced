# Spec: mark card as done

## Requirements

### REQ-1. Элемент управления на карточке

Карточка содержит видимый элемент управления (чекбокс или кнопка), которым пользователь может поставить или снять отметку `isDone`.

### REQ-2. Сохранение на сервере

При изменении отметки клиент отправляет `PATCH /cards/:id` с телом `{ isDone: boolean }`. Сервер сохраняет значение.

### REQ-3. Переживание обновления страницы

После обновления страницы значение `isDone` загружается с сервера и отображается корректно.

### REQ-4. Эндпоинт

- Метод: `PATCH`
- Адрес: `/cards/:id`
- Тело запроса: `{ isDone: true }` или `{ isDone: false }`

### REQ-5. Валидация (middleware)

Значение `isDone` должно быть `boolean`. Негодное значение отклоняется кодом 400. Проверка реализована в middleware, а не в контроллере.

### REQ-6. Карточка не найдена (контроллер)

При изменении несуществующей карточки возвращается 404. Решение принимает контроллер; сервис лишь сообщает, что карточки нет.

### REQ-7. Сервис без HTTP-зависимостей

В сервисе нет `req`, `res` и статус-кодов. Только бизнес-логика.

### REQ-8. Разделение слоёв

- Роутер: одна строка — привязка `PATCH /cards/:id` к контроллеру.
- Контроллер: функция `patchCardDone`.
- Сервис: функция `updateCardDone(cardId, isDone)`.
