# Design: mark card as done

## Решение

- **Метод:** `PATCH`
- **Адрес:** `/cards/:id`
- **Тело запроса:** `{ isDone: boolean }`

Идентификатор карточки находится в адресе — операция адресована конкретной карточке.

## Обоснование

Меняется одно поле карточки, а не вся карточка целиком. PATCH предназначен для частичного обновления ресурса, PUT — для полной замены. PUT потребовал бы присылать все поля карточки, что избыточно и неудобно на клиенте.

## Альтернативы

| Альтернатива | Почему не подошла |
|---|---|
| `PUT /cards/:id` | Заменяет ресурс полностью — нужно слать все поля карточки, избыточно при изменении одного поля. |
| `POST /cards/:id/done` | Глагол в адресе нарушает REST-принципы; не умеет снимать отметку (нет способа передать `false`). |

## Слои

### Роутер

Одна строка в `cards.routes.ts`:

```
router.patch("/:id", validateCardDone, patchCardDone);
```

### Middleware

Функция `validateCardDone` проверяет, что `req.body.isDone` имеет тип `boolean`. Негодное значение (например, `undefined`, `"true"`, `0`) отклоняется кодом 400. Проверка живёт в middleware, а не в контроллере.

### Контроллер

Функция `patchCardDone(req, res)` в `cards.controller.ts`:

1. Вызывает `cardsService.updateCardDone(req.params.id, req.body.isDone)`.
2. Если сервис вернул `null` — отвечает 404.
3. Иначе — отвечает 200 с обновлённой карточкой.

Решение про 404 принимает контроллер; сервис лишь сообщает, что карточки нет.

### Сервис

Функция `updateCardDone(cardId, isDone)` в `cards.service.ts`:

- Принимает только `cardId: string` и `isDone: boolean`.
- Возвращает обновлённую карточку или `null`.
- Не содержит `req`, `res` и статус-кодов — только бизнес-логика.
