# Proposal: delete-card-api

## Контекст
В теме 2 был реализован тикет KAN-2 — удаление карточек на клиенте (React-компонент). Клиентская функция `deleteCard` в `client/src/api/cards.ts` отправляет `DELETE /api/cards/${id}` и не ждёт тело ответа (`Promise<void>`).

После переезда на свой сервер (тема 3) удаление сломалось: сервер не знает роут `DELETE /cards/:id` и отвечает 404 HTML-страницей Express по умолчанию. Клиент выбрасывает ошибку, карточка не удаляется.

## Проблема
- Сервер не обрабатывает `DELETE /cards/:id`
- Неизвестные пути возвращают HTML вместо JSON
- Нет обработчика неожиданных ошибок
- Нет валидации существования карточки перед удалением

## Цель
Реализовать серверную половину тикета KAN-2: роут удаления карточки, корректную обработку 404 и общий error-middleware. Клиент не меняется.

## Критерии приёмки
1. Удаление карточки работает с доски: карточка исчезает и не возвращается после F5
2. Идентификатор удаляемой карточки берётся из пути запроса (`req.params.id`)
3. Попытка удалить несуществующую карточку возвращает 404 JSON и не роняет сервер
4. Запрос на любой неизвестный адрес возвращает JSON со статусом 404
5. В приложении есть обработчик неожиданных ошибок со статусом 500
6. Код клиента не изменён
