# Design: delete-card-api

## Выбранный подход

### Роут DELETE /cards/:id
Используем `app.delete("/cards/:id", handler)`. ID берём из `req.params.id`. Ищем карточку в массиве через `findIndex`, удаляем через `splice`. Отвечаем 204 через `res.status(204).end()`.

### Обработчик 404 для неизвестных путей
Регистрируем `app.use((req, res) => {...})` **после всех роутов**. Он сработает только для запросов, которые не подошли ни одному роуту выше. Отвечаем JSON со статусом 404.

### Error-middleware
Регистрируем `app.use((err, req, res, next) => {...})` **после 404-обработчика**. Четыре параметра обязательны — Express распознаёт error-middleware именно по количеству параметров. Логируем ошибку, отвечаем 500 JSON.

## Отклонённые альтернативы

### Альтернатива 1: Статус 200 вместо 204
Можно было ответить 200 с телом `{"success": true}`. Отклонено: клиент не использует тело ответа (`Promise<void>`), 204 семантически точнее.

### Альтернатива 2: Удаление через filter вместо splice
Можно было сделать `cards = cards.filter(c => c.id !== id)`. Отклонено: `splice` мутирует существующий массив, что согласуется с тем, как работает `push` в POST-роуте. Единый стиль мутации.

### Альтернатива 3: Вынести роуты в отдельный файл
Можно было создать `server/routes/cards.ts`. Отклонено: сервер пока маленький (один файл), вынос преждевременен. Сделаем, когда роутов станет больше.
