# Proposal: mark-card-done

## Why

На доске не видно, какие карточки выполнены. У карточек есть поле `isDone`, но установить его невозможно — оно только приходит с сервера и не меняется. Из-за этого фильтр «выполненные» бесполезен, а пользователь не может отметить задачу как законченную.

## What

- Клиент: на каждой карточке появляется элемент управления (чекбокс / кнопка), которым отметка `isDone` ставится и снимается.
- Клиент: состояние сохраняется на сервере через `PATCH /cards/:id` и переживает обновление страницы.
- Сервер: новый эндпоинт `PATCH /cards/:id` с телом `{ isDone: boolean }`.
- Сервер: middleware валидирует значение `isDone` — отклоняет небулево кодом 400.
- Сервер: контроллер обрабатывает 404 при отсутствии карточки; сервис лишь сообщает об отсутствии.
- Сервер: в сервисе нет `req`, `res` и статус-кодов.

## Scope

### In scope

- **Сервер**
  - Роут: `PATCH /cards/:id` — одна строка в файле роутов.
  - Контроллер: функция `patchCardDone(req, res)` — вызывает сервис, формирует ответ 200 / 404.
  - Сервис: функция `updateCardDone(cardId, isDone)` — только бизнес-логика, без `req`/`res`.
  - Middleware: валидация поля `isDone` (должен быть boolean), код 400 при нарушении.
- **Клиент**
  - Элемент управления на карточке (чекбокс / кнопка) для переключения `isDone`.
  - Запрос `PATCH /cards/:id` при изменении состояния.
  - Не более 2–3 новых файлов на клиенте.

### Out of scope

- Пакетное изменение `isDone` для нескольких карточек.
- Изменение других полей карточки через этот же эндпоинт.
- История изменений `isDone` (аудит-лог).
- Реалтайм-синхронизация между клиентами (WebSocket).

## Impact

- **Сервер:** новый роут, контроллер-функция, сервис-функция, middleware.
- **Клиент:** компонент-элемент управления на карточке + запрос к API (2–3 файла).
- **Существующие роуты, контроллеры и компоненты** — без изменений, кроме интеграции нового элемента управления.
