# Spec: server-side done filter

## Purpose
Описывает поведение системы при серверной фильтрации карточек по полю `is_done` через параметр строки запроса `done`.

## ADDED Requirements

### Requirement: Параметр строки запроса done
Клиент SHALL передавать параметр строки запроса `done` в запросе `GET /cards`. Параметр определяет, какие карточки должны быть возвращены сервером.

#### Scenario: Параметр отсутствует
- **WHEN** запрос `GET /cards` не содержит параметра `done`
- **THEN** сервер выполняет SQL-запрос без условия `WHERE is_done`
- **THEN** возвращаются все карточки

#### Scenario: Параметр равен "false" (фильтр включён)
- **WHEN** запрос `GET /cards?done=false`
- **THEN** сервер выполняет SQL-запрос с условием `WHERE is_done = $1` со значением `false`
- **THEN** возвращаются только невыполненные карточки

#### Scenario: Параметр равен "true" (показать только выполненные)
- **WHEN** запрос `GET /cards?done=true`
- **THEN** сервер выполняет SQL-запрос с условием `WHERE is_done = $1` со значением `true`
- **THEN** возвращаются только выполненные карточки

#### Scenario: Неизвестное значение параметра
- **WHEN** запрос `GET /cards?done=1` или `GET /cards?done=yes` или `GET /cards?done=`
- **THEN** сервер отвечает кодом 400 с JSON `{ "error": "..." }`

### Requirement: Серверная фильтрация через SQL
Сервер SHALL выполнять отбор карточек внутри SQL-запроса с использованием параметризованного условия `WHERE is_done = $1`. Карточки не должны отсеиваться повторно на уровне приложения после получения строк.

#### Scenario: Фильтрация в репозитории
- **WHEN** запрос содержит `done=false`
- **THEN** репозиторий выполняет `SELECT ... FROM cards WHERE is_done = $1 ORDER BY created_at DESC` с `$1 = false`
- **THEN** сервис и контроллер не выполняют дополнительной фильтрации

#### Scenario: Отсутствие фильтрации в приложении
- **WHEN** сервер вернул список карточек из базы
- **THEN** ни контроллер, ни сервис не вызывают `.filter()` для отсечения карточек по `isDone`

### Requirement: Безопасная подстановка параметра
Значение параметра `done` SHALL попадать в SQL-запрос только через параметризованный плейсхолдер `$1`. Склейка строк (template literals, `+`, `concat`) для подстановки значения `done` недопустима.

#### Scenario: Параметр передан как $1
- **WHEN** репозиторий выполняет запрос с фильтром
- **THEN** запрос содержит `$1` и значение передано как второй аргумент `pool.query(sql, [value])`

### Requirement: Ответ при пустом результате
Если под фильтр не подошло ни одной карточки, сервер SHALL ответить кодом 200 с пустым JSON-массивом `[]`.

#### Scenario: Нет невыполненных карточек
- **WHEN** запрос `GET /cards?done=false` и все карточки выполнены
- **THEN** сервер отвечает 200 с телом `[]`

#### Scenario: Нет выполненных карточек
- **WHEN** запрос `GET /cards?done=true` и ни одна карточка не выполнена
- **THEN** сервер отвечает 200 с телом `[]`

#### Scenario: Доска показывает пустую колонку
- **WHEN** сервер ответил 200 с пустым массивом `[]`
- **THEN** доска показывает пустую колонку, а не сообщение об ошибке загрузки

### Requirement: Переключение фильтра перезапускает запрос
При изменении состояния переключателя «скрыть выполненные» клиент SHALL отправить новый запрос к серверу с актуальным значением параметра `done`.

#### Scenario: Включение фильтра
- **WHEN** пользователь включает переключатель «скрыть выполненные»
- **THEN** клиент отправляет `GET /cards?done=false`
- **THEN** ключ `useQuery` включает `hideDone`, что запускает новый запрос

#### Scenario: Выключение фильтра
- **WHEN** пользователь выключает переключатель «скрыть выполненные»
- **THEN** клиент отправляет `GET /cards` без параметра `done`
- **THEN** возвращаются все карточки
